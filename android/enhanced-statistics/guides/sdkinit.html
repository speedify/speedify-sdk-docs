Implementing AutoConstruct

In your Application class, implement SpeedifySDK.AutoConstruct:

// Implement SpeedifySDK.AutoConstruct
class MyApplication : Application(), SpeedifySDK.AutoConstruct {

  // ...

  override fun getSpeedifySDK(context: Context): SpeedifySDK {
    // instantiate a new SDK object
    val sdk = SpeedifySDK(context, "My App Title", object : SpeedifyHandler() {
      // override wanted methods here
    })

    // If using Dispatch, add on the Dispatch library
    Dispatch.getInstance(context)

    // If using Enhanced Statistics, add on the Enhanced Statistics library
    EnhancedStatistics.getInstance(context)

    return sdk
  }

  // ...

}

// Implement SpeedifySDK.AutoConstruct
public class MyApplication extends Application implements SpeedifySDK.AutoConstruct {

  // ...

  @Override
  public SpeedifySDK getSpeedifySDK(Context context) {
    // instantiate a new SDK object
    SpeedifySDK sdk = new SpeedifySDK(context, "My App Title", new SpeedifyHandler() {
      // override wanted methods here
    });

    // If using Dispatch, add on the Dispatch library
    Dispatch.getInstance(context);

    // If using Enhanced Statistics, add on the Enhanced Statistics library
    EnhancedStatistics.getInstance(context);

    return sdk;
  }

  // ...

}

Starting the Speedify SDK

Before you use the Speedify SDK in your app, you must initialize VPN permission.

  // check for vpn permission, and request it if needed
  if (!SpeedifySDK.hasVPNPermission(this)) {
    SpeedifySDK.initializeVPNPermission(this)
  }

  // check for vpn permission, and request it if needed
  if (!SpeedifySDK.hasVPNPermission(this)) {
    SpeedifySDK.initializeVPNPermission(this);
  }

When you want to start the Speedify SDK, call this to get an instance of the SDK.

  val sdk = SpeedifySDK.getInstance(context)

  SpeedifySDK sdk = SpeedifySDK.getInstance(context);

Logging In

You must be logged in before you can connect. A fresh SDK starts in the LOGGED_OUT state; once authenticated it moves to LOGGED_IN, from which you can connect. State changes are delivered to OnState (see Receiving State in Your UI).

Choose one of:

  • login(username, password) — a Speedify account.
  • loginOAuth(token) — an OAuth access token. This is an enterprise feature that requires additional backend development; contact Connectify for more information about implementing this for your organization.
  • loginAutoAccount() — an automatically generated, device-bound account. This is the lowest-friction option for getting a VPN running without a login screen.
  • getActivationCode() — activate the device from a browser instead of entering credentials in-app. Useful for TVs, set-top boxes, and other limited-input devices.

The current state is delivered to OnState (call refreshState to fetch it on demand); there is no synchronous state getter. Drive login from your state receiver:

  override fun OnState(state: Types.State) {
    if (state == Types.State.LOGGED_OUT) {
      sdk.loginAutoAccount()   // or login(user, password) / loginOAuth(token)
    }
  }

  @Override
  public void OnState(Types.State state) {
    if (state == Types.State.LOGGED_OUT) {
      sdk.loginAutoAccount();   // or login(user, password) / loginOAuth(token)
    }
  }

The activation-code flow is a two-step login. Call getActivationCode, then handle OnActivationCode, which delivers an activationCode and an activationUrl. Present those to the user (for example, render the URL as a QR code); they open the URL in a browser, sign in, and enter the code to authorize this device. On success the SDK transitions to LOGGED_IN like any other login — watch OnState.

Login failures are reported via OnLoginError. If login fails even with valid credentials, confirm your app has been authorized — see Prerequisites. Call logout to log out.

Optional: Application onCreate

The Speedify SDK starts up a background process to run the VPN. If you initialize other components in your Application's onCreate, you may need to return early to avoid initializing them in this process as well.

  override fun onCreate() {
    super.onCreate()

    // ... common initialization ...

    if (SpeedifySDK.IsBackgroundProcess(this)) return

    // ... other initialization that you only want to run in your app's UI process ...
  }

  @Override
  public void onCreate() {
    super.onCreate();

    // ... common initialization ...

    if (SpeedifySDK.IsBackgroundProcess(this)) return;

    // ... other initialization that you only want to run in your app's UI process ...
  }

Receiving State

To drive your UI you register an ISdkStateReceiver, whose callbacks run in your process — see Receiving State in Your UI. This is distinct from the SpeedifyHandler below, some of whose callbacks run in the SDK's background process.

Optional: Handlers

If you do not specify a custom SpeedifyHandler in getSpeedifySDK, you can call setHandler on your SpeedifySDK object to set one later. Note that some callbacks on the ISpeedifyHandler happen in Speedify SDK's background process. If you want to implement these, use the SpeedifySDK.AutoConstruct method above.

Optional: SDK Cleanup

To close down the SDK entirely without exiting your application, call SpeedifySDK.ForceExit(context). To restart the SDK, you must either obtain a new SpeedifySDK object or call restartServices on your old SpeedifySDK object.
