Speedify SDK for Android 17.2.1/ Guides/ The Two Core Classes

Everything you build on the Speedify SDK revolves around two classes:

  • SpeedifySDK — the command side. Obtained with getInstance (see Initializing the SDK). Every method on it — login, connect, settings — returns immediately; nothing on this class blocks or returns a result directly.
  • ISpeedifyHandler — the callback side. Results, errors, and state changes all arrive here. Extend SpeedifyHandler (which provides empty defaults for everything) and override what you need. Some of its callbacks run in the SDK's background process; to drive UI, register the ISdkStateReceiver subset in your UI process instead — see Receiving State in Your UI.

Commands in one direction, events in the other: your app calls a SpeedifySDK method, then reacts to the callback that reports the outcome. The one piece of state that matters most is State, delivered on OnState.

The Essential Flow: Log In, Then Connect

A VPN session is two steps, and each is a single call:

1. Log in — once. From LOGGED_OUT, authenticate with one of login, loginOAuth, or getActivationCode (sign in from a browser — ideal for TVs and other limited-input devices). On success the SDK reaches LOGGED_IN, stores the credentials, and from then on logs itself back in every time it starts — you do not call login again on later launches. See How Often to Log In for details and the exceptions.

2. Connect. From LOGGED_IN, call connectAuto — with CLOSEST it picks the nearest server for you. The SDK walks through CONNECTING to CONNECTED, reporting the chosen server on OnConnectedServer. To pick a specific server instead, use connectByCountry, connectByCity, or connectByServer.

Failures arrive on OnLoginError and OnConnectError; disconnect returns to LOGGED_IN.

Put together, the smallest useful app is a handler that reacts to state:

class MyHandler(private val context: Context) : SpeedifyHandler() {

  override fun OnState(state: Types.State) {
    val sdk = SpeedifySDK.getInstance(context) ?: return
    when (state) {
      // Not a place to log in: the SDK passes through LOGGED_OUT at startup
      // while its own stored-credential login is in flight. Sign in from your
      // own UI on first run, and again only when OnLoginError says the stored
      // credentials stopped working.
      Types.State.LOGGED_OUT -> { /* nothing to do here */ }
      // LOGGED_IN is also the state after a manual disconnect, so gate the
      // connect on your app's own intent rather than connecting unconditionally.
      Types.State.LOGGED_IN -> if (userWantsVpn) sdk.connectAuto(Types.AutoConnectMethod.CLOSEST)
      Types.State.CONNECTED -> { /* tunnel is up */ }
      else -> { /* transitional states */ }
    }
  }

  override fun OnLoginError(errorType: Types.ErrorType?, message: String?) {
    // credentials rejected / token expired / network trouble
  }
}

public class MyHandler extends SpeedifyHandler {
  private final Context context;

  public MyHandler(Context context) { this.context = context; }

  @Override
  public void OnState(Types.State state) {
    SpeedifySDK sdk = SpeedifySDK.getInstance(context);
    if (sdk == null) return;
    switch (state) {
      case LOGGED_OUT:
        // Not a place to log in: the SDK passes through LOGGED_OUT at startup
        // while its own stored-credential login is in flight. Sign in from your
        // own UI on first run, and again only when OnLoginError says the stored
        // credentials stopped working.
        break;
      case LOGGED_IN:
        // LOGGED_IN is also the state after a manual disconnect, so gate the
        // connect on your app's own intent rather than connecting unconditionally.
        if (userWantsVpn) sdk.connectAuto(Types.AutoConnectMethod.CLOSEST);
        break;
      case CONNECTED:
        // tunnel is up
        break;
      default:
        // transitional states
        break;
    }
  }

  @Override
  public void OnLoginError(Types.ErrorType errorType, String message) {
    // credentials rejected / token expired / network trouble
  }
}

Pass your handler to the SpeedifySDK constructor in getSpeedifySDK, or attach it later with setHandler.

Everything else the SDK offers — server selection, per-connection settings, statistics, sharing — hangs off this same skeleton: a SpeedifySDK call, answered by a callback.
