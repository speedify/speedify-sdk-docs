Speedify SDK for Android 0.0.0.1/ Guides/ Receiving State in Your UI

This is the central pattern for any app built on the SDK: how connection state, the server directory, settings, statistics, and network-sharing events get from the SDK to your UI.

Two Processes

The SDK runs its VPN engine and daemon in a separate background process (:vpnservice); your Activities and UI run in your app's main process. This is why getSpeedifySDK is called in each process, and why your Application.onCreate should return early in the background process:

  @Override
  public void onCreate() {
    super.onCreate();
    if (SpeedifySDK.IsBackgroundProcess(this)) return;
    // ... UI-process-only initialization ...
  }

Handler vs. State Receiver

There are two ways to receive callbacks, and choosing the right one is important:

  • SpeedifyHandler / ISpeedifyHandler — set on the SDK object (see Initializing the SDK). Some of its callbacks run in the :vpnservice background process, so it is the right place for things like the foreground notification (UpdateForegroundNotification), but you cannot touch your UI objects from there.

  • ISdkStateReceiver — registered with sdkStateReceivers. Its callbacks run in the process that registered it, so register it from your UI process and use it to drive your UI. This is what most apps want.

ISdkStateReceiver has an empty default implementation for every method, so you only override the events you care about (e.g. OnState, OnConnectedServer, OnDirectory, OnSettings).

Registering a Receiver

IMPORTANT : Registered receivers are held by a weak reference, so you must keep a strong reference to your receiver yourself (e.g. a field on a long-lived object or singleton). If the only reference is the one you passed to register, it will be garbage-collected and your callbacks will silently stop.

  public class VpnState extends ISdkStateReceiver {  // keep a strong reference to this instance

    public void start(Context context) {
      SpeedifySDK sdk = SpeedifySDK.getInstance(context);
      sdk.sdkStateReceivers.register(this);   // callbacks run in this (UI) process
      // Pull the current values so your UI isn't empty until the next change:
      sdk.refreshAll();
    }

    public void stop(Context context) {
      SpeedifySDK sdk = SpeedifySDK.getInstance(context);
      if (sdk != null) sdk.sdkStateReceivers.unregister(this);
    }

    @Override
    public void OnState(Types.State state) {
      // marshal to your UI thread and update
    }

    @Override
    public void OnConnectedServer(Types.ServerInformation serverInfo) { /* ... */ }
  }

Callbacks may arrive on a background thread — marshal updates to your UI thread (e.g. a Handler, runOnUiThread, LiveData.postValue, or a StateFlow).

Pulling Current Values

Registering only delivers future changes. To get the current snapshot, call the matching refresh* method, each of which triggers its callback: refreshState → OnState, refreshDirectory → OnDirectory, refreshSettings → OnSettings, and so on. refreshAll is a shortcut that refreshes everything.

Setters follow the same convention: each setter's documentation names the callback that reports its current value (for example setKillswitch's value is reported on OnPrivacySettings as PrivacySettings.killswitch, not on OnSettings).

Connection Statistics

Live throughput and per-connection stats are off by default. Enable them with enableStatUpdates:

  // OnConnectionStats once/sec, OnAdaptersList every 30s, OnSessionStats & OnStreamingStats once/sec
  sdk.enableStatUpdates(true, null);

The second argument (periods) is not the update interval — connection stats always arrive once per second. It is the list of timeframes (in hours) for the session stats reported on OnSessionStats, with SessionStatPeriods.PERIOD_CURRENT / PERIOD_TOTAL for the current session / lifetime totals; pass null to keep the previously configured periods.

OnConnectionStats delivers a ConnectionStatsGroup containing one ConnectionStats per connection. The aggregate tunnel throughput is reported on the synthetic connection whose adapterID is "speedify"; the other entries are the individual underlying connections. To show total download/upload, read receiveBps / sendBps from the "speedify" entry:

  @Override
  public void OnConnectionStats(Types.ConnectionStatsGroup group) {
    for (Types.ConnectionStats c : group.connections) {
      if ("speedify".equals(c.adapterID)) {
        long downBps = c.receiveBps;
        long upBps   = c.sendBps;
        // update UI
      }
    }
  }

Note that some per-connection fields (loss, local IP, in-flight bytes, …) are not populated on the "speedify" aggregate entry.
